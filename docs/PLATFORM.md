# 通用平台模块

研究方法、报告与财务分析属于业务层。以下模块不依赖报告正文，可以在其他多用户 AI 应用中复用：

| 模块 | 职责 | 配置/存储 |
|---|---|---|
| `server/auth.py` | 账号、密码哈希、会话、管理员身份与停用 | `users`、`sessions` |
| `server/platform_policy.py` | 会员等级、默认等级、会话/邀请期限、时区与用量操作名称 | 可选的 `VC_PLATFORM_CONFIG` JSON |
| `server/accounts.py` | 会员额度、原子用量预留与结算、一次性邀请 | `account_settings`、`research_usage`、`invite_codes` |
| `server/settings_store.py` | 按用户隔离的模型配置、密钥脱敏、增删与切换 | `user_settings` |
| `server/llm_client.py` | OpenAI/Anthropic 兼容调用与演示模式 | 当前用户启用配置 |

## 角色、会员与用量

管理员与初始管理员是权限角色；会员等级仅决定额度，不能通过升级会员获得管理权限。初始管理员的 ID 保存在数据库中，不依赖个人用户名。新库默认引导账号名为 `admin`，必须显式设置自己的密码。

平台策略可自定义 1–12 个等级。例如用 `basic/team` 替代默认 `free/vip/svip`，同时设置对应 `default_tier`。标识需以小写字母开头，限小写字母、数字、下划线和连字符；名称与每日额度独立。管理员 API 与页面由同一策略生成。

管理员保存的额度优先于策略文件默认值。已有数据库中的等级 ID 和配额不会在部署时重置。调整策略时保留已有用户使用的等级；需要改名时先修改显示名称，需要改 ID 时另行做显式的数据迁移。

## 积分扩展边界

现有计量单位为 `request`：业务调用 `accounts.reserve(user_id, action)` 取得预留标识，再调用 `finish(reservation_id, success)` 完成或释放。消费记录独立于报告，不因删除报告而返还次数；重复完成不会重复计次。`usage_actions` 可用于其他业务动作的显示名称。

若需要可充值积分，应以同一事务边界增加不可变积分流水、余额预留、幂等业务键及退款记录，并为每个动作明确成本。现版本没有积分余额、充值或支付接口，也不会把请求次数伪装为货币价值；避免在通用化时改变已有用户的消费规则。

## 模型配置

新用户只有无密钥的演示配置，Base URL 与模型名为空。服务商预设是用户显式选择时的便利输入，不是私人配置。旧用户已有连接参数保持原值，不从部署机器的 SSH 配置继承任何模型密钥。

应用配置、SSH 运维配置与每用户模型配置分开。平台策略文件不允许密钥等未知字段；私人策略文件、环境文件、数据库与备份不属于公开源码。
