# AI Berkshire Web

基于 [AI Berkshire](https://github.com/xbtlin/ai-berkshire) 的社区 Web 封装，使用 FastAPI + SQLite + 原生 HTML/CSS/JavaScript。研究方法与技能基础来自 [xbtlin/ai-berkshire](https://github.com/xbtlin/ai-berkshire)；本应用提供在网页配置 API Key / Base URL / 模型、调用技能和阅读管理报告的使用方式。

感谢原作者 [xbtlin](https://github.com/xbtlin) 开源研究框架。本项目并非上游官方 Web 客户端，纯 API 适配也不等同于 Claude Code / Codex 的完整工具环境；完整方法、原生用法与技能更新请优先查阅上游。

## 本地启动与生产更新

```bash
cd ai-berkshire-web
# 仅全新数据库需要；请设置自己的强密码
export VC_ADMIN_PASS='替换成至少8位的独立强密码'
python run.py
```

- Python 3.10+；`run.py` 自动安装缺失的运行依赖。研究框架默认由管理员主动同步，启动时不下载研报。也可先 `python -m pip install -r requirements.txt`。
- 访问 `http://127.0.0.1:8765`。Windows PowerShell 使用 `$env:VC_ADMIN_PASS = '自己的强密码'`。
- `VC_ADMIN_USER` 默认 `admin`，仅用于首次创建与旧库初始管理员识别；`VC_ADMIN_PASS` 不覆盖已有用户密码。没有既有用户时必须显式设置至少 8 位管理员密码。
- `VC_DATA_DIR` 可指定独立数据目录，默认 `ai-berkshire-web/data/`。测试必须使用隔离目录，禁止指向生产数据库。
- 使用单个应用进程。不要用多个 Uvicorn workers 运行本地 SQLite/线程任务模式；启动会释放上一次进程中断的用量预留。
- 本地开发更新代码后重启本地应用；生产环境通过根目录 `python -m ops.remote deploy --ref <已推送的提交>` 发布，不在服务器发布目录中执行 git pull 或手动覆盖源码。流程为本地检查、直接推送 main、本机 SSH 部署，无需 PR、CI 或 GitHub Secrets。
- 生产部署自动备份、切换版本、验证既有核心数据和服务健康。数据库升级幂等执行，保留既有账号、密码、禁用状态、配置和研究记录。部署后刷新浏览器获取新静态资源；完整操作见 [运维文档](../ops/README.md)。
- 根 `.env.local` 仅提供本机 SSH 运维参数，不会自动被 `run.py` 读取。服务器运行配置由已有 systemd 环境文件提供；模型配置继续按用户保存在 SQLite。

## 工作空间

| 页面 | 主要交互 |
|---|---|
| 新建研究 | 方法搜索与分类，选择方法后填写标的，市场及动态参数，单篇/多视角生成，近期研究快速继续 |
| 研究流水线 | 1–30 个候选；仅执行选中的阶段，固定依次筛选/清单/深度；结果保留淘汰理由 |
| 研究记忆 | 已索引报告检索与带来源问答，结论库；资料未命中时不调用模型、不计次 |
| 观点时间线 | 搜索公司/专题、公司目录分组翻页、每页 20 份报告回看评分与结论 |
| 研究历史 | 个人记录搜索、回看、删除；删除不退回研究额度 |
| 报告库 | 官方及站内共享报告统一检索，来源/范围筛选，近期重复研究提示；直接阅读不计次 |
| 我的账户 | 角色、会员等级、今日用量与明细，修改密码，生成和复制邀请链接 |
| 用户管理 | 搜索和等级筛选、会员等级、禁用/启用、密码重置，注册及额度规则；权限按角色限制 |
| 模型设置 | 个人多配置管理、脱敏密钥、连接测试；不同用户的配置完全隔离 |

桌面保留常驻侧栏；800px 及以下使用抽屉导航。报告阅读器提供目录、复制、Markdown 下载与显式专注阅读，点击正文不会意外切换全屏。确认、删除和密码重置使用页面内对话框，支持键盘焦点与 Escape。长表格局部横向滚动，页面不会被撑宽。

全站表单使用统一的 44px 控件、固定可见标签与一致的焦点/禁用状态。报告库、时间线、历史和研究记忆的关键词、选择器与日期位于同一筛选网格，操作按钮独立成行；自定义日期展开在完整行内。桌面按字段数量分列，平板缩为两列，手机单列排列，避免长选项撑宽。研究参数、流水线阶段、模型设置、账户及用户管理沿用同一控件规范；手机输入文字为 16px，便于阅读并避免输入时自动放大。

阅读器标题与来源信息放在左侧，桌面右侧“复制 / 下载 / 全屏 / 关闭”同高对齐，关闭按钮单独分隔；手机将操作组放到标题和来源信息下方，关闭按钮保持右上角，触摸目标至少 44px。普通弹窗与全屏阅读使用相同布局，滚动正文时操作始终可见。

报告工具栏使用无文字图标，鼠标悬停或键盘聚焦时显示提示，屏幕阅读器可读取每个按钮的操作名称。进入全屏后图标和提示同步切换为退出全屏，退出或关闭报告后恢复。

登录页与侧栏使用统一的 AI Berkshire Web 矢量标志（AB 字母与罗盘方向），网页标签栏声明 SVG、PNG 和多尺寸 ICO 图标，移动端书签使用 180px 图标。品牌资产位于 `static/brand/`，无远程字体或图片依赖；入口自动为资源生成内容版本号，避免旧图标缓存。

## 角色与会员

会员等级由 `VC_PLATFORM_CONFIG` 的 `membership_tiers` 配置；默认 `free / vip / svip`，与 `is_admin` 管理角色分离：

| 能力 | 会员等级 | 管理员 | 初始管理员 |
|---|---|---|---|
| 研究、报告阅读、个人设置、邀请 | 是 | 是 | 是 |
| 研究额度 | 按等级 | 不限 | 不限 |
| 管理普通会员等级、禁用、重置密码 | 否 | 是 | 是 |
| 修改账户规则 | 否 | 是 | 是 |
| 管理其他管理员、任命管理员、删除用户 | 否 | 否 | 是 |
| 全站敏感数据导出与导入 | 否 | 否 | 是 |

初始管理员身份绑定持久化用户 ID，升级后不因用户名或启动过程被重新提升、启用。初始管理员不能被删除、停用或取消管理角色。管理员可使用个人账户页面修改自己的密码。

禁用账号和重置密码立即撤销该用户的全部会话；重新启用不会恢复旧会话。本人修改密码需验证当前密码，成功后所有设备重新登录。新注册/新设置的密码至少 8 位；既有密码登录保持兼容。

## 每日额度与注册

默认基础会员 20 次/天、标准会员 200 次/天、高级会员不限，管理员不限。等级的标识、显示名称和默认额度均可在平台策略中配置，管理页自动生成选项与额度表单。管理员实时调整 0–10000 的整数，0 表示不限。

- 新建研究、流水线、命中资料的记忆问答、深度抽取每次预留 1 次额度；多视角研究整体计 1 次。
- 用量独立保存在 `research_usage`，同一用户并发预留原子执行。删除报告、切换设备或刷新页面不会清空用量。
- 任务无产出失败释放额度；已有部分产出的中断计 1 次。进行中的任务显示为已预留。
- 按平台策略的时区每日零点恢复，默认 Asia/Shanghai；修改等级/规则即时影响可用上限。
- 旧库现有历史只迁入用量一次，不改写报告正文或用户配置。服务重启时释放未完成任务的预留。
- 注册默认开放。可开启“必须提供会员推荐码”；全部会员均可生成邀请，一次使用，有效期和每日生成上限由平台策略配置，默认 72 小时、每天 20 个。
- `/?invite=推荐码` 链接自动打开注册并预填；失败注册不会消耗邀请，过期或已使用的邀请不再提供复制链接按钮。

## 研究状态与模型

报告库、个人研究历史、观点时间线（公司目录与报告页）、研究记忆结论库和问答资料来源均支持报告日期筛选：全部日期、近 1 周、1 / 3 / 6 / 12 个月、自定义起止日期、日期未知。除新建研究的近期参考默认近 6 个月外，其余入口默认全部日期。起止日均包含；月份、北京时间及日期有效性规则统一。日期未知不替代为导入时间、文件修改时间或索引时间，选择全部日期仍可找到这些资料。历史按生成日期筛选且保持账户隔离；记忆问答在相关性排名截取前过滤资料，所选范围无资料时不调用模型、不计额度。

各报告列表使用可点击的数字页码、当前页高亮及“第 N 页，共 M 页”，并保留上一页/下一页。近期参考、报告库、个人历史、结论库和时间线均按筛选后的总数计算页数；改变日期或搜索条件回到第一页。记忆问答修改日期不自动生成回答，下次点击提问时生效。筛选只影响查询，不重建索引、不修改已有报告或模型结论。

新建研究的“已有研究参考”默认查询近 6 个日历月，可切换近 1 周、1 / 3 / 6 / 12 个月；范围按北京时间报告日期计算并展示实际起止日期。官方、站内生成、本地导入统一过滤后按日期排序，每页预览 3 份，数量为完整匹配总数。月份按对应日回溯，遇短月份取月末；周范围含今天共 7 天。日期未知、无效或在未来的报告不计入近期，导入时间和文件修改时间不替代报告日期；仍可从“查看全部历史”进入报告库查询。

匹配只使用标题、公司/专题和研究参数等目录元数据，不扫描报告正文，避免仅顺带提及公司就提示已有该标的研究。提示只表示相关参考，不能保证研究范围或数据时点一致；直接查看不调用模型，也不拦截新建研究。查询支持分页、8 秒超时及重试；更换输入或时间范围时取消旧请求，迟到响应不会覆盖当前结果。

观点时间线使用独立的轻量报告目录，覆盖官方、站内生成和本地导入。可按公司/专题名称搜索，目录每组显示 30 个选项，所有匹配结果都可翻页访问；目录不读取报告正文、不等待研究记忆全文索引锁。报告目录更新或站内数据变化时自动刷新目录缓存。

时间线按报告日期倒序，每页仅整理 20 份报告，可查看较早/较新的页面。报告总数覆盖整个公司/专题；评分走势、首末评分和结论变化明确只代表当前页，不将本页统计当成全部历次研究。未知日期不虚构，未识别的评分保持为空，不同满分口径的评分不合并绘图。优先读取已有深度抽取，其他报告使用规则整理，不调用模型、不占额度、不改写既有研究记忆或模型抽取数据。超长正文只扫描首尾摘要区段并在页面标明，完整正文仍可打开阅读。

规则整理结果保存在持久目录 `timeline_cache.db`，按报告版本与整理规则版本失效：翻回已看过的页面可复用；源报告更新或规则变化后重新整理。该缓存可重建，故障时直接读取报告，不阻断页面；它不属于用户历史或模型配置，也不会被误作已有深度抽取。公司列表请求 8 秒、时间线请求 12 秒超时，提供重试；搜索新公司或离开页面会取消旧请求，旧响应不会覆盖当前选择。

入口 HTML 使用重新验证缓存策略，脚本、样式和标志的 URL 自动带内容版本号，避免升级后旧脚本搭配新版页面而停在“加载中”。

支持 OpenAI 兼容、Anthropic 和演示模式，多组模型配置可独立新增、编辑、启用、删除。密钥留空表示保留，显式清除才删除。配置存于服务器 SQLite，每个用户一份，不是浏览器本地配置。无 Key 时明确提示演示模式；演示内容不得当作真实研究结论。

四个研究视角及综合步骤均使用请求用户的配置；流水线演示检测也传递用户 ID。流式返回 NDJSON，包含 `delta / done / error` 等事件，只有收到完成事件才显示成功。错误不再悄悄变成完成；无效或缺失的筛选 JSON 不自动把公司判为通过。断开流水线会阻止后续阶段启动，已完成阶段留在历史中；正在等待上游响应的请求可能需要等其返回后才能释放资源。

单篇、多视角研究及记忆问答在等待模型首字、角色结果或综合结果时，每 10 秒发送一个空行保活，避免连接因长时间没有正文而超时；保活不计入正文，也不表示研究完成。服务端有界队列保持传输背压，断开连接后由生成线程安全收尾、保存已有内容和结算用量；即使在响应头或第一段正文发出前断开，也会释放未使用的额度预留，避免残留“运行中”。多视角研究会等已发出的角色请求退出后再结算，发布保护在这期间仍生效。网络错误提示前往研究历史核对结果，不再一律要求修改 API Key；此机制不能恢复用户断网的连接，也不会自动重跑收费模型请求。

API Key、自定义请求头和调用参数按用户隔离。新用户以空地址、空模型、空密钥的演示配置开始；服务商预设只在主动选择时填入。用量与会员策略独立配置，积分扩展边界见平台架构文档；不代付模型调用。

流水线筛选会从模型输出中解析唯一、完整的 JSON 结果数组，兼容代码块和附带方括号的说明，忽略 `<think>` 推理段。公司名必须与输入完全匹配，结论必须为布尔值；无效或有歧义的结果会自动重试一次，仍失败时提示具体阶段并保留此前成果。重试属于同一次流水线，不额外计研究额度。

## 数据、备份与共享

| 数据 | 位置 |
|---|---|
| 用户/密码哈希/会话 | `app.db`: `users / sessions` |
| 用户模型配置 | `app.db`: `user_settings` |
| 个人历史与全站共享报告 | `app.db`: `history` |
| 本地导入报告、相对路径与导入者 | `app.db`: `imported_reports` |
| 角色根身份与额度规则 | `app.db`: `account_settings` |
| 不依赖报告删除的研究用量 | `app.db`: `research_usage` |
| 邀请与使用状态 | `app.db`: `invite_codes` |
| 可重建研究记忆 | `memory.db` |
| 官方报告缓存 | `reports_cache.json` |

上述相对位置均在应用的持久数据目录中。本地默认为 `ai-berkshire-web/data/`；生产默认使用服务器 `/var/lib/ai-berkshire-web/`，与每次发布的源码和虚拟环境分离。常规代码更新复用已有数据目录和共享研究框架，不随源码重新初始化。

生成报告继续进入全站共享池。个人历史管理、账户用量、模型配置保持用户隔离，管理身份不会绕过个人查询。官方报告、既有共享报告与全局研究索引维持原有共享范围。

数据库、会话、模型密钥及密码哈希永不提交 Git。迁移备份含敏感数据，请离线妥善保存。

```bash
python migrate-data.py export ../.local/backups/backup.zip
python migrate-data.py import ../.local/backups/backup.zip
```

全站网页导出/导入只对初始管理员开放。导出使用 SQLite backup API，包含 WAL 中已提交数据；导入先验证数据库、备份当前库，有研究任务进行时拒绝导入，恢复后迁移账户表并撤销导入的登录会话。需使用导入数据库中的账号重新登录。

以上命令在本地应用目录执行，导出目标在忽略入库的 `.local/` 中。跨环境迁移时单独安全传输备份；CLI 使用所处进程的应用 `VC_DATA_DIR`，不会自动读取 systemd 的运行配置。生产数据迁移需先明确目标数据目录和恢复范围。

部署备份保存在服务器 `VC_BACKUP_DIR` 的独立目录，格式为全数据目录 `data.tar.gz` 和核心记录的 `continuity.json` 哈希基线。它与上述 ZIP 数据迁移用途和格式不同。代码回退不会自动覆盖恢复数据库；数据恢复需另行明确目标备份与范围。

上游框架默认位于仓库根 `ai-berkshire/`，也可通过 `VC_FRAMEWORK_DIR` 指定。不入 Git，默认不自动下载。管理员主动同步后才读取外部技能与公开报告。源码目录中的旧 `shared-reports/` 不再自动导入，研报导出到 Git 的旧接口返回 410。

生产发布目录中的 `ai-berkshire/` 是指向服务器共享框架的链接，常规部署不更新其内容。研究历史保存在持久数据目录，不随代码提交或公开源码导出。迁移报告使用网页导入与管理员数据备份。

管理员在报告库中“同步官方仓库”时，先克隆并检查技能、报告索引和财务工具，再在框架目录内部暂存完整的新副本，保留部署链接、共享目录及本地 `.git.bak/`。复制失败时旧框架不变，文件切换失败时自动恢复旧文件；恢复也失败时保留目录内的 `.upstream-sync-*/previous/` 并在同步状态中给出位置，供管理员定向恢复。成功后自动重建官方报告索引，站内共享报告仍从原数据库读取。

### 导入本机 AI Berkshire 报告

打开“报告库 → 导入报告 → 选择 reports 文件夹”，在系统文件选择器中选择本机目录，例如 `C:\research\reports`。浏览器上传所选目录中的报告及相对路径，无需服务器访问本机磁盘，也不需要粘贴路径。也可选择多个 Markdown 文件。

预览会识别 Markdown 标题、公司/专题、研究类型和日期，可取消勾选个别报告。优先采用根 `index.json` 中的元数据，其次使用简单 front matter、一级标题、子目录和文件名；日期无法识别时保留为空，显示“日期未知”。保留正文（仅规范 BOM、换行及首尾空白）和完整相对路径。支持 `.md` / `.markdown`，包括底稿、审计等研究产物；跳过 README、隐藏文件及非 Markdown 文件，不上传图片、PDF 或模型配置。单篇最多 4 MiB，每次选择最多 200 MiB / 10000 个文件，浏览器自动分批预览和导入。

预览不写入数据；确认后报告以“本地导入”来源加入全站共享池，导入者归当前账号，文件内的作者 ID 不赋予账户权限。所有已登录用户可搜索、阅读、复制和下载；“本地导入 → 只看我的”可筛选本人的导入，只有导入者可删除。删除仅影响网站副本，不操作本机源文件。

同一公司、同一天、同类型乃至同标题的多份报告，只要内容不同均独立保存，报告列表与阅读器展示来源相对路径供区分。以当前账号和规范化正文哈希去重（覆盖同批、跨批及并发重试）；即使文件名、目录或相对路径不同，正文相同也只导入一份。忽略 BOM、换行风格与首尾空白的差异；不会按公司、日期、类型或标题合并正文不同的报告。同一路径正文修改后追加新版本，不覆盖旧报告。导入中断时已完成批次保留，重试跳过相同正文。导入不调用模型，不写研究历史或用量。数据保存于 `app.db` 独立表，随全站数据备份、迁移及部署连续性验证保留，不受官方仓库同步影响。报告数据不进入源码或开源导出包。

## 接口

| 范围 | 主要接口 |
|---|---|
| 登录与注册 | `POST /api/auth/login`, `/register`, `/logout`; `GET /api/auth/me`, `/policy` |
| 本人账户 | `GET /api/account/usage`; `PUT /api/account/password` |
| 邀请 | `POST /api/invite/generate`; `GET /api/invite/list` |
| 用户与规则 | `GET /api/admin/users`; `PUT/DELETE /api/admin/users/{id}`; `POST /api/admin/users/{id}/reset-password`; `GET/PUT /api/admin/account-policy` |
| 方法与研究 | `GET /api/skills`, `/api/skills/{id}`, `/api/skills/{id}/params`; `POST /api/research/run`, `/api/pipeline/run` |
| 研究成果 | `/api/history*`, `/api/reports*`, `/api/memory*`, `/api/timeline*` |
| 本地报告导入 | `POST /api/reports/import/preview`, `POST /api/reports/import`; `DELETE /api/reports/imported/{id}`；报告来源筛选 `source=imported` |
| 配置 | `GET/POST /api/settings`; `PUT/DELETE /api/settings/{id}`; `POST /api/settings/{id}/activate`, `/api/settings/test` |
| 维护与迁移 | `/api/admin/sync-status`, `/sync-ai-berkshire`, `/data/*` |

使用 `Authorization: Bearer <session-token>`，受保护接口以当前会话身份授权。邀请码不是登录凭据。

## 本地验证

完整应用和运维检查从仓库根执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r ai-berkshire-web/requirements-dev.txt -r ops/requirements.txt
.\.venv\Scripts\python.exe -m ops.check
```

检查入口为测试设置隔离数据目录，不加载 SSH 配置或调用真实模型。没有自动 CI，检查结果由本地执行负责。仅验证应用时，也可在 `ai-berkshire-web/` 目录使用：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
node --check static/app.js
node --check static/workspace.js
node --test static/__tests__/*.cjs
git diff --check
```

自动化验证包括新库/旧库迁移、权限边界、用户隔离、原子额度预留、失败计次、一次性邀请、会话撤销、流式错误、模型身份传递、筛选结果校验、Markdown 安全渲染。

`tests/smoke_server.py` 提供完全隔离的界面测试服务（测试资料和演示模型），不得用于生产。`python -m ops.check --browser --playwright-module <模块绝对路径>` 会启动并关闭该服务，检查桌面/手机登录、研究生成、账户、用户管理、导航和报告阅读。Playwright 安装、截图位置和 Windows/Linux 的验证差异见 [运维文档](../ops/README.md#本地检查)。

本工具仅供学习研究，不构成投资建议。公开部署请配置 HTTPS，并在入口反向代理设置合理的登录/注册限速和请求体大小限制。
